# 失败案例库（跨项目，按失败类别）

配套 `SKILL.md` 使用：**主干给流程与门槛，这份给"为什么"。** 每条格式固定：
症状（用户/线上看到什么）→ 根因（一句话）→ 防线（能自动化的写成命令/用例，不能写的写成人工检查点）→ 证据（可复核的出处）。

**证据列是出处标记，不是可点击链接**（原始文档属作者工作区，不随本仓库分发）。缩写约定：

| 缩写 | 指向 |
|---|---|
| `规范:x-y` | 作者工作区的插件开发规范（含 CASE-01…CASE-20 全文），行号区间 |
| `CHANGELOG:x` | 开源插件 [acmerQQ-group-bot](https://github.com/td1336065617/acmerQQ-group-bot) 的 `CHANGELOG.md` |
| `补丁记录` / `排查报告` / `工作记录` | 作者工作区的事故与排查记录 |
| `QM:y` / `NR:y` / `LG:y` / `MN:y` | 群管理 / 昵称登记 / 登录守卫 / 菜单导航 四个插件的 `CHANGELOG.md` |
| `实现文档` / `PERF` / `CONFIG` / `缓存方案` / `打卡热力图方案` 等 | 同上工作区对应主题文档 |

读法：把它当**案例索引**——先看"症状"和"防线"两列（这两列不依赖出处即可执行），需要追根溯源时再按缩写去找原文档。

## F. 数据、缓存与迁移
